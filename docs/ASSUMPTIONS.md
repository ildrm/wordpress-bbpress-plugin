# Assumptions and operating limits

The [original catalog](ORIGINAL_PROMPT.md) remains authoritative. [FINAL_REVIEW.md](FINAL_REVIEW.md) records the completed local implementation review and exact evidence. These decisions describe actual behavior and deployment responsibilities.

1. Supported baseline: WordPress 6.6+, PHP 8.2+, bbPress 2.6+, InnoDB. Native minimum/current matrices use WP 6.6/PHP 8.2.34 and WP 7.1/PHP 8.4.26 with bbPress 2.6.19/BuddyPress 14.5.2/MariaDB. Windows PHP 8.2.12 is a development host, not a production recommendation. Hosted CI is defined but has not been run remotely.
2. AI is optional and disabled by default. Provider/model identifiers do not promise ongoing availability, pricing or billing accuracy. Secrets come from protected server configuration. Actual vendor accounts and model evaluations need operator validation.
3. All BuddyPress group forums, private/hidden/password sources and unapproved metadata are excluded from external AI. Pending text may be prepared locally only with an explicit boolean opt-in; it remains restricted, receives no embeddings and is withheld from retrieval until native publication.
4. At most ten accepted replies, twelve transferred evidence sources and bounded native provenance are admitted. Confirmation labels and relevance are explanatory signals, not calibrated statistical certainty or official site policy.
5. Portable lexical/vector/feed/profile work deliberately bounds candidates and pages. The local vector backend scans at most one thousand candidates; measured maximum-dimension lookup takes seconds. Large sites should benchmark and select an indexed adapter rather than assume exhaustive million-post retrieval.
6. Private replies are conditional in original section 43 and are not implemented. Native replies inherit topic/forum restrictions. Polling is the supplied realtime transport; websocket infrastructure is optional.
7. Optional PWA navigation is a generic reconnect screen and caches no discussions/messages. Explicit encrypted composer copies use nonpersisted passphrases/keys, account/site/source authenticated ciphertext and 24-hour expiry. Recovery needs online identity/source/sanitization checks. Device ciphertext removal is an explicit browser action.
8. Templates and composer guidance preserve existing native editor text. The maintained native WordPress/bbPress editor supplies core formatting and scheduling. No-JavaScript forms remain usable; optional selections do not become hidden analytics.
9. Email is off by default; site mail infrastructure, real unsubscribe/preference navigation and live browser-vendor push delivery need deployment testing. At-least-once workers cannot promise exactly-once remote delivery after a crash.
10. Moderation signals and AI triage are advisory. Human changes use native actions and audit trails. Summaries/articles retain provenance and human locks/edits; automatic conversion creates drafts only. Independent adapters must preserve the documented privacy/consent contracts.
11. Default uninstall preserves data. Explicit removal retains bbPress posts, human editorial articles and public Media Library files. Owned protected bytes, malformed/refusal recovery and native single-site/network retention have actual local tests.
12. No remote publishing/deployment, credentials or user accounts were assumed. Automated axe/native keyboard/RTL and semantic review do not claim a live screen-reader certification. Local representative workload budgets are regression checks, not production hosting SLAs.
13. Runtime dependency advisories and frontend advisories have current recorded results. A later complete Composer development-dependency refresh timed out against the registry; the hosted full-lockfile audit remains defined and must run in the operator's networked CI. No failed/partial audit is labelled successful.

See [admin](ADMIN_GUIDE.md) and [operations](OPERATIONS.md) for deployment configuration and [verification](VERIFICATION.md) for actual history.
