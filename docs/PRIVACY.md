# Privacy and data flow

The site stores member signals, source relationships, reputation/audit events, notification preferences, drafts, fields, files, reports and optional messages. There is no remote telemetry. Saved keyword searches are explicit account-owned records and are never aggregate analytics or externally processed. Search analytics store UTC aggregates rather than raw questions or per-member search histories.

| Processing | Leaves the site? | Control |
| --- | --- | --- |
| Local solutions/search/duplicates/feeds | No | Native source permissions |
| External text/embeddings | Redacted question and public source excerpts/explicit public AI fields | Disabled by default; server key plus admin enablement |
| Email | Generic activity URLs and preference link to configured mail transport | Member email mode defaults off |
| Browser push | Encrypted generic activity through browser vendor endpoint | Module configuration and explicit device permission |
| Public attachments | Public Media Library files | Labelled as public; URLs remain public |
| Protected attachments | Bytes only through authorized download | Confirmed directory outside web roots |
| Private messages | Stored in site database; selected report copied for moderators | Optional module, membership, block and retention |

Private, hidden, password-protected and BuddyPress group forums are excluded from the bundled external AI adapter. Local policy filters may further restrict. Redaction is heuristic, not guaranteed identification of all personal or confidential information. Provider retention, training, region and contract terms are operator responsibilities; request `store:false` does not replace provider contractual review.

WordPress Tools integrates member export and erasure in bounded pages. Export excludes push authentication keys and operational storage keys. Erasure removes signals/follows/preferences/drafts/subscriptions, atomically reverses signal reputation, repairs poll totals, redacts owned messages and copied sender evidence, anonymizes reporting/solution/audit/advisory-requester references and removes attachment bytes when the original backend is available. Unavailable file backends keep a recoverable reference and disclose required operator cleanup.

Forum posts and editorial articles retain their native content workflows. A request does not silently delete bbPress discussions. Other authors' authored content is never included as the requesting member's data. Reports and audit timestamps/types may be retained after identity removal.

Retention defaults to 90 days, configurable 7–3,650. Daily bounded cleanup expires operational notifications, closed cases, completed/dead jobs, drafts/messages/message reports/push/AI feedback/moderation advisories and old aggregate metrics. Nonzero reputation ledger events remain for explainability. Large backlogs require repeat CLI batches. Conversation membership/structural records can outlive deleted message bodies.

Do not cache restricted discussion content in the browser. The PWA worker caches no responses; offline navigation gets a generic reconnect message. Device permission is requested only on an explicit button action.

Optional achievements store a badge identifier, supporting public source IDs and up to twenty award/revocation transitions with explanations. Personal export includes owned badge records and the per-blog achievement preference. Erasure removes owned badge records and retains a minimal per-blog opt-out preference to prevent queued regeneration. The member may explicitly re-enable achievements in their hub. This preference and badge records are removed by explicitly requested uninstall cleanup; badges do not change native content ownership or capabilities.

Saved-search alerts require a separate opt-in for each owned query. Matching stays local. Job payloads contain native source IDs and batch cutoffs rather than keyword text or participant lists. Internal matches do not contribute to aggregate search counters. Current access, mutes and account eligibility are rechecked before delivery; privacy erasure removes the query and cancels its pending matches. Source publication markers have no owner or query text and are removed when that native post is permanently deleted.

Erasure cancels owned saved queries before clearing notification rows. A consumer retains its query lock through delivery, so cancellation waits for any consumer already processing and notification cleanup then removes its committed alert. An actual two-process InnoDB fixture verifies this ordering. This does not disable future activity for the WordPress account; explicitly saving and enabling a new query constitutes new participation.

Mention fallback queries current native members for an authorized discussion and stores no copied member directory. Delivery stores the existing source/member event identity and follows current recipient visibility/mutes/preferences. Configuration audit retains only known changed field names or definition counts, actor and time; it excludes values, unknown setting keys, credentials and editorial text. These events use ordinary operational retention and actor/subject anonymization.

Enabled BuddyPress keeps native mention parsing and delivery. When Forum Intelligence notifications are enabled, native bbPress topic/reply activity is guarded by filtering native recipients before saving and again before BuddyPress updates unread counts or sends alerts. Current source access, account eligibility, source/category mutes and author publication limits apply; at most five of twenty examined native candidates survive. The guard stores no recipient directory and does not replace BuddyPress email preferences or ordinary activity mentions. Previously stored native unread mentions remain under BuddyPress ownership and are not exposed by this plugin's notification center.

Opt-in encrypted composer copies use localStorage, separately from response/service-worker caches. Records contain salt, IV, ciphertext and version/expiry/revision metadata; hashed origin/blog/account/source keys reveal that copies exist, not plaintext. No passphrase or encryption key is persisted or sent to the server. The page retains a nonextractable WebCrypto key while unlocked; locking releases references rather than promising JavaScript heap zeroization. Recovery is valid for 24 hours by the browser clock; ciphertext remains until removal or browser storage cleanup. WordPress privacy export, erasure, retention and uninstall cannot remotely delete device-local ciphertext. Deleted or changed accounts cannot pass online recovery authorization. The generic offline navigation shell stays unchanged. Recovered title/body are sent to WordPress for sanitization and can enter ordinary server autosave; they are never sent to AI by this feature. Password managers, extensions and compromised same-origin scripts are outside this protection.

Composer preview sends the author's current text to the same WordPress site for authorization and HTML preparation, never to an AI provider. It creates no records/events/provider jobs or preview caches. The native redirect adapter rejects preview/decrypted-text preparation before dispatch, preventing their result text from entering redirect transients. The inert preview strips active links/media and uses a script-free sandbox/CSP; host pages can still load their own native resources. The WordPress suggested privacy-policy text includes encrypted device copies, recovery/server-autosave behavior and limits of remote erasure.

Contextual question guidance is site editorial configuration rather than member profiling. Optional question-type/product/category choices remain in the open composer and are not persisted or sent to external AI. Global rules intentionally appear in any currently readable forum; forum-scoped guidance is excluded from other forum catalogs. Configuration audit retains only definition counts. Administrators should keep secrets and private troubleshooting logs out of guidance intended for public forums.

Optional administrator ranking explanations add transient response metadata only. They do not create query histories, copied source records, audit entries, jobs or a second provider call. Each search retains its existing anonymous UTC aggregate metric. Ordinary members and moderator-only accounts cannot enable the diagnostic response; current native authorization still determines every visible source.

Answer grounding now uses the actual bounded, redacted public transfer text. The ask service supplies each text adapter with at most twelve sources, each at most 3,000 characters, and redacted instructions at most 1,000 characters. Summary and moderation-advisory services also prepare public evidence through the shared projection before calling replacement text adapters. Summaries transfer at most twelve sources / 3,000 characters each; advisories transfer one source / 3,000 characters. Index embedding inputs are redacted and bounded to 12,000 characters; query embeddings to 500, while local query/source text stays unchanged. The bundled compatible adapter retains its additional redaction. These are character bounds, not a claim about a provider's token budget. The ask service adds no raw-question telemetry or stored evidence/answer transcript. Search-only fields with AI transfer disabled remain local. A readable private result may appear in its authorized reader's fallback but cannot approve public-only answer generation. Best-effort redaction is not a guarantee that all sensitive text is detected.

A generated answer's grounding metadata includes two public support IDs and an opaque reader/site-bound signature. It carries no raw query, private-source fingerprint or provider internals. The signature also covers the rendered answer/citations and original support hashes. Native saved responses remain reader-scoped five-minute transients; proof validation does not generate another answer or record another search/ask event. Previously saved generated responses lacking a proof are invalidated.

Advisory display rechecks moderator access to the current case and requires the saved advisory's source binding to match that case. Reassignment cannot make old unreadable-source detail visible through a newly readable discussion; incomplete legacy bindings require regeneration. Generation also rejects case-source changes during provider work. Summary generation renews the actor's current moderation permission and topic access after provider completion before storing output.

Knowledge article provenance stays in native post metadata. Every stored source must still be readable before native article or revision read/edit/delete and plugin/generic body/excerpt/title display; the origin topic alone is insufficient. Article passwords and native draft/private/revision rights also apply to display. Core may return its generic protected-post excerpt placeholder without article text. Human edits remain stored when a source becomes restricted and regain authorized access when source access is restored. Incomplete legacy provenance is withheld and requires editorial repair or a fresh reviewed source-bound draft; the plugin does not guess missing sources or silently delete articles.


Issued answer-feedback receipts expire after fifteen minutes and bind the current account/site, native topic, qualifying/accepted sources and public source hashes. Stored feedback contains a category, human review state, source fingerprints and response hash; it retains no query or generated-answer transcript and invokes no external training. Current private/deleted/unavailable sources suppress reports and saved answer controls. Erasure removes owned reports and anonymizes relationship creators on the current site while retaining approved relationships and native discussions. Review identity stays in the auditable actor field rather than a second payload copy.

The bundled provider's logging mode is configurable as off, failures only or usage plus failures. It records numeric aggregates only; no mode records credentials, evidence or generated text. Request limits and security audits remain active. Optional pending-content preparation is local-only and retains restricted classification; pending content is withheld from retrieval and external AI until native publication.
